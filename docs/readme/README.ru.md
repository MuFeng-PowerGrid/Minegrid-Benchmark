# MINEGRID

### От моделей энергосистем к мультимодальному рассуждению

MINEGRID объединяет подробные нелинейные описания оборудования, изображения с аннотациями и дополнительные инструкции по сетям. Библиотека моделей служит основой небольшого исследовательского симулятора, а мультимодальный бенчмарк — для изучения понимания схем управления и электрических сетей моделями VLM.

## Создание небольшого симулятора энергосистемы

Используйте HTML как спецификации небольшого симулятора: общий интерфейс оборудования, согласованные единицы и системы координат, сохранение ограничений, совместные уравнения сети и устройств, инициализация, интегрирование и события. Это основа исследовательского прототипа и реализации с помощью LLM с последующей независимой инженерной проверкой.

### Согласование динамики с моделями PSCAD и PowerFactory

Если требуется высокоточное согласование динамических характеристик с моделями PSCAD, PowerFactory или аналогичных программ, описания TypicalApparatus можно использовать как исходную структуру. Методы из работ [Guo и Shi (2024)](https://doi.org/10.1109/CIEEC60922.2024.10583352) и [Shi, Guo и др. (2026)](https://doi.org/10.1109/TSTE.2025.3621702) позволяют получать явные аналитические выражения уравнений модели по данным переходных процессов с учётом физических ограничений, используя идентификацию моделей и символьную регрессию.

Согласуйте единицы измерения, системы координат и граничные условия с эталонной моделью. Проверяйте обобщающую способность на рабочих точках и возмущениях, не использованных при идентификации, сравнивая полученные переходные процессы с результатами эталонной программы. Примеры реализации доступны в [DSIPS — Dynamic Sparse Identification of Power System](https://github.com/gdg1999/DSIPS).

## Примеры запросов

### 1 · От описания к компоненту

```text
Используй приложенную HTML-модель MINEGRID VSG как спецификацию. Перечисли состояния, алгебраические переменные, входы, выходы, параметры, единицы и системы координат. Определи интерфейсы f(x,z,u;p), g(x,z,u;p) и тока, отдаваемого в сеть. Сохрани все ограничения и anti-windup. Отдели заданные значения от недостающих данных; не выдумывай параметры. До написания кода представь план и соответствие уравнений коду.
```

### 2 · Сборка небольшого динамического симулятора

```text
По приложенным описаниям синхронного генератора, GFM, GFL и нагрузки спроектируй исследовательский симулятор трёхузловой сети. Определи общие базы, сетевые уравнения, интерфейсы и согласованную инициализацию. Добавь малое изменение нагрузки, запись состояний/токов/напряжений, проверку невязок и сходимости по шагу. Перечисли отсутствующие сетевые параметры и дополнительные допущения. Раздели реализованные функции и непроверенное поведение.
```

## Оценка VLM и исследование их механизмов

- Оценка возможностей: распознавание блоков, знаков обратной связи, состояний и вывод DAE; извлечение узлов/ветвей, связности и таблиц сети.
- Исследование механизмов: контролируемые изменения языка, разрешения, перекрытия и положения символов; классификация ошибок восприятия и физического рассуждения; анализ активаций при доступе к внутренним данным модели.
- Протокол: исключайте эталонные ответы из входа, фиксируйте состав задач и сложностей, оценивайте структуру и физическую согласованность, группируйте общие источники для снижения утечки. Точного совпадения текста недостаточно для эквивалентных уравнений.

## Структура и формат аннотаций

```text
JSON Index/
├── device_control_*/      # JSONL
└── network_topology_*/     # JSONL
Multimodal/
├── Alpaca Data/
│   ├── Apparatus/          # HTML
│   ├── Network/            # JSON
│   └── General Knowledge/  # JSON
├── apparatus_{easy,medium,hard}/
└── network_{easy,medium,hard}/
Scripts/
docs/
├── assets/
└── readme/
```

Запись JSONL содержит id, image, conversations и annotations. Пути изображений отсчитываются от корня. Значение ответа ассистента нужно повторно разобрать как JSON. Исходный запрос — на китайском; annotations содержит en, es, ar, fr и ru. Шесть языков README не означают шесть независимых переводов ответов. Дополнительные JSON — массивы записей instruction/input/output.
